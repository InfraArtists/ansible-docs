# Ansible Playbook & Role Structure

## Let's start with bad practice :)


```yaml
---
- name: Basic server setup
  hosts: youtube-servers
  tasks:
    - name: Create directory in /home
      ansible.builtin.file:
        path: /home/dir1
        state: directory
        owner: root
        group: root
        mode: "0755"

    - name: Install htop
      ansible.builtin.apt:
        name: htop
        state: present

    - name: Make sure ssh service is running
      ansible.builtin.service:
        name: ssh
        state: started
```

```bash
ansible-playbook -i myserver simple.yml
```


A typical project is laid out like this:

```
project/
├── inventory/      # your hosts file(s)
├── plays/          # your playbook(s)
└── roles/
    └── my-role/
        ├── defaults/main.yml   # default variables (lowest priority, meant to be overridden)
        ├── vars/main.yml       # role variables
        ├── files/              # static files to copy as-is
        ├── templates/*.j2      # files with variables inside, rendered with Jinja2
        ├── tasks/main.yml      # the list of tasks the role runs
        ├── handlers/main.yml   # actions triggered by tasks (start/stop/restart a service, etc.)
        └── meta/main.yml       # role metadata: author, dependencies, etc.
```

A **role** is just a reusable, self-contained bundle of tasks/vars/files for one piece of config (e.g. "install nginx"). Instead of creating these folders by hand, you can scaffold one with:

```bash
ansible-galaxy init roles/my-role
```

## Building the example

**1. Create the project:**

```bash
mkdir -p project/inventory project/plays project/roles
```

**2. Inventory** — `inventory/myserver`:

```ini
[youtube-servers]
192.168.122.40
192.168.122.50
```

**3. Role tasks** — `roles/my-role/tasks/main.yml`:

```yaml
---
# short (key=value) syntax — quick to write, but flagged by ansible-lint (see note below)
- name: Create dir0 in /home
  ansible.builtin.file: path=/home/dir0 state=directory owner=root group=root mode=0755
  tags:
    - create_dir0

# standard form
- name: Create directory in /home
  ansible.builtin.file:
    path: /home/dir1
    state: directory
    owner: root
    group: root
    mode: "0755"
  tags:
    - create_dir

- name: Create dir2 in /home
  ansible.builtin.file:
    path: /home/dir2
    state: directory
    owner: root
    group: root
    mode: "0755"
  tags:
    - create_dir2

- name: Create file in dir1
  ansible.builtin.file:
    path: /home/dir1/file1
    state: touch
    owner: root
    group: root
    mode: "0755"
  tags:
    - create_file

- name: Install htop
  ansible.builtin.apt:
    name: htop
    state: present
  tags:
    - install_htop

- name: Make sure ssh service is running
  ansible.builtin.service:
    name: ssh
    state: started
  tags:
    - start_ssh
```

This follows [ansible-lint](https://ansible.readthedocs.io/projects/lint/) conventions:
- Fully-qualified module names (`ansible.builtin.file` instead of `file`).
- Full YAML syntax only — no `key=value` free-form args.
- `mode` quoted as a string (`"0755"`), so it's never misread as a number.
- `tags` written as a list, even with a single tag.

**4. Playbook** — `plays/myproject.yml`, referencing the role:

```yaml
---
- hosts: youtube-servers
  roles:
    - my-role
```

## Running it

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml
```

Run it a second time — tasks that already match the desired state turn up **green** ("ok") instead of **yellow** ("changed"), since Ansible only changes what isn't already correct.

Useful flags:

- `-vvv` — verbose output, for debugging what Ansible is actually doing.
- `-t` / `--tags` — run only the tasks matching one or more tags:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --tags "create_dir,create_file"
```
