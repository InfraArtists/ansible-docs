# Playbooks

A playbook is like a to-do list with checkmarks — it describes the desired end state, and Ansible works through it step by step.

- **Inventory**: where should I go (which hosts).
- **Playbook**: what should I do (which tasks).

A playbook is made up of **plays**, a play is made up of **tasks**, and a task runs a **module**:

```
playbook → play(s) → task(s) → module
```

Example:

```yaml
# site.yml
- name: Configure web servers          # a play
  hosts: webservers
  become: true
  tasks:
    - name: Install nginx              # a task
      apt:                             # the module
        name: nginx
        state: present

    - name: Start nginx
      service:
        name: nginx
        state: started
```

Run it with:

```bash
ansible-playbook site.yml
```

# Ansible Configuration

Ansible reads its config from the first of these locations it finds (checked in this order):

1. `ANSIBLE_CONFIG` — an environment variable pointing to a config file, e.g. `ANSIBLE_CONFIG=./my.cfg ansible-playbook site.yml`
2. `./ansible.cfg` — in the current directory
3. `~/.ansible.cfg` — in your home directory
4. `/etc/ansible/ansible.cfg` — system-wide default

You can generate a starter file (all defaults, commented out) instead of writing one from scratch:

```bash
ansible-config init --disabled > ansible.cfg
```

## Common settings (under `[defaults]`)

| Setting | Meaning |
|---|---|
| `inventory` | Path to the inventory file |
| `library` | Path to custom Ansible modules |
| `forks` | Max number of hosts processed in parallel |
| `remote_port` | SSH port used to connect to hosts |
| `log_path` | Where Ansible writes its log file |
| `transport` | Mechanism used to connect/transfer files (e.g. `smart`, `ssh`) |
| `timeout` | Connection timeout, in seconds |
| `remote_tmp` | Temp path on the remote host used to copy, run, then clean up modules |
| `roles_path` | Path where roles are looked up |
| `ask_pass` / `ask_become_pass` / `ask_vault_pass` | `true`/`false` — prompt for SSH / sudo / vault password |
| `command_warnings` | Warn when you use the raw `shell`/`command` module instead of a dedicated module |
| `deprecation_warnings` | `true`/`false` — show warnings for deprecated features |

Example `ansible.cfg`:

```ini
[defaults]
inventory = ./hosts
remote_port = 22
forks = 10
timeout = 30
```

### `gathering` — fact-collection behavior

Controls when Ansible auto-collects host facts (`ansible_facts`, see [02.md](02.md)) at the start of a play:

- **implicit** (default): facts are gathered automatically, unless a play sets `gather_facts: false`.
- **explicit**: facts are *not* gathered unless a play sets `gather_facts: true`.
- **smart**: gathers facts once per host and caches them, skipping re-gathering if already collected.

```ini
[defaults]
gathering = smart
```
