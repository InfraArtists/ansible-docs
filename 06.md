# Useful `ansible-playbook` Flags

A handful of flags make running and debugging playbooks a lot easier. All examples below reuse the playbook from [05.md](05.md):

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml
```

## `--syntax-check` — validate before you run

Checks the playbook's YAML/syntax without connecting to any host. Always worth running first.

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --syntax-check
```

## `--check` — dry run

Reports what *would* change, without actually changing anything on the servers.

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --check
```

## `--diff` — show the actual changes

Combine with `--check` to see a before/after diff of any file Ansible would modify — great for reviewing a change before applying it for real.

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --check --diff
```

## `--list-tasks` / `--list-tags` — see what's inside

List the tasks a playbook would run, or just the tags it defines, without executing anything:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --list-tasks
ansible-playbook -i inventory/myserver plays/myproject.yml --list-tags
```

## `--tags` / `--skip-tags` — run a subset of tasks

`--tags` runs only the tasks matching the given tag(s); `--skip-tags` does the opposite:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --tags "create_dir"
ansible-playbook -i inventory/myserver plays/myproject.yml --skip-tags "install_htop"
```

## `--start-at-task` — resume from a specific task

Skips everything before the named task — handy after a playbook fails partway through and you don't want to redo what already succeeded:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --start-at-task "Install htop"
```

## `--step` — confirm each task interactively

Pauses before every task and asks what to do:

- `y` — run this task
- `n` — skip this task
- `c` — stop asking, run everything from here on

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --step
```

## `-e` / `--extra-vars` — override variables at run time

Passes (or overrides) a variable for this run only, without touching any file:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml -e "ansible_user=milad"
```

## `--flush-cache` — force fresh fact-gathering

Clears the cached facts from a previous run (see `gathering = smart` in [04.md](04.md)) so the playbook re-collects them instead of reusing stale ones.

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --flush-cache
```

## `--limit` — target a subset of hosts

Runs against only the given host(s), even though the playbook targets a whole group — useful for testing on one server first:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --limit 192.168.122.40
```

## `--list-hosts` — see who it would run against

Prints the hosts matched by the playbook (and any `--limit`), without running anything:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --list-hosts
```

## `-v`, `-vv`, `-vvv` — increase verbosity

More `v`s means more output — `-v` shows task results, `-vvv` shows connection/module debug info. Useful when a task fails and you need to see why.

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml -vvv
```

## `-f` / `--forks` — control parallelism

Sets how many hosts Ansible works on at the same time (default is 5). Raise it when you have many hosts and want the run to finish faster:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --forks 20
```

## `-K` / `--ask-become-pass` — prompt for the sudo password

Asks for the `become` (sudo) password interactively instead of reading it from config or a vault — handy when it isn't stored anywhere:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml -K
```

## `-u` / `--user` — connect as a different user

Overrides the SSH user for this run, instead of the one set in inventory or `ansible.cfg`:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml -u milad
```

## `--private-key` — use a specific SSH key

Points Ansible at a particular private key file, useful when a host needs a different key than your default `~/.ssh/id_rsa`:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --private-key ~/.ssh/myserver_key
```

## `-e @file.yml` — load extra vars from a file

`-e`/`--extra-vars` also accepts a YAML/JSON file (prefixed with `@`), so you don't have to cram everything onto the command line:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml -e @vars/prod.yml
```

## `--ask-vault-pass` / `--vault-password-file` — unlock encrypted files

If any vars are encrypted with `ansible-vault`, one of these is required so Ansible can decrypt them at run time — the first prompts for the password, the second reads it from a file:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --ask-vault-pass
ansible-playbook -i inventory/myserver plays/myproject.yml --vault-password-file ~/.vault_pass
```

## `-k` / `--ask-pass` — prompt for the SSH password

Asks for the SSH login password interactively, for hosts you connect to with a password instead of a key:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml -k
```

## `--become-user` / `--become-method` — control privilege escalation

By default `become` (see `-b` in [03.md](03.md)) escalates to `root` using `sudo`. Override either when a host needs something else:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml --become-user deploy --become-method su
```

## `-c` / `--connection` — change the connection type

Switches how Ansible reaches the host — `ssh` is the default; `local` is handy for running tasks against the control machine itself:

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml -c local
```

## `-T` / `--timeout` — connection timeout

Sets how many seconds to wait for a host to respond before giving up (see `timeout` in `ansible.cfg`, [04.md](04.md)):

```bash
ansible-playbook -i inventory/myserver plays/myproject.yml -T 60
```
