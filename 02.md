# Ansible Ad-hoc Commands

First, generate an SSH key on your Ansible machine and copy it to your servers. Ansible connects over SSH, so your public key needs to be on every server it manages.

```bash
ssh-keygen
ssh-copy-id USER@yourserverip
```

## Test connectivity

```bash
ansible -m ping localhost   # or your server's IP address
```
```
localhost | SUCCESS => {
    "changed": false,
    "ping": "pong"
}
```

## What is an ad-hoc command?

An ad-hoc command runs a single task on one or more hosts, without writing a playbook — useful for quick, one-off jobs.

```bash
ansible -u <USER> -m <MODULE> -a "<ARGS>" <HOSTS>
```

Add your hosts (IP or hostname) to `/etc/ansible/hosts` so you can reference them by name or group.

### `shell` module — run a command

```bash
ansible -u milad -m shell -a "ls -l /var" youtube-servers
```
```
127.0.0.1 | CHANGED | rc=0 >>
total 48

drwxrwxrwt 16 root root 4096 Aug 23 23:28 tmp
```

```bash
ansible -u milad -m shell -a "df -h" 127.0.0.1
```

### `setup` module — gather facts

Collects information about a host (IP addresses, OS, hardware, etc.) as variables prefixed with `ansible_`.

```bash
ansible -u milad -m setup 127.0.0.1
```
```
127.0.0.1 | SUCCESS => {
    "ansible_facts": {
        "ansible_all_ipv4_addresses": ["192.168.178.108"],
        "ansible_apparmor": { "status": "enabled" },
        ...
    }
}
```

Filter facts down to just what you need with `filter=`:

```bash
ansible -u milad -m setup -a "filter=ansible_nodename" youtube-servers
```
```
127.0.0.1 | SUCCESS => {
    "ansible_facts": {
        "ansible_nodename": "milad-norouzi-PC"
    },
    "changed": false
}
```
